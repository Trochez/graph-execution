# Pax autonomous v2 — local operator and qualification guide

This is a candidate, not a production release. Use the existing isolated Python 3.12/Pax 0.74 environment, a locally trusted Docker daemon, an existing persistent loopback Temporal dev service and approved OpenAI-compatible route. The old restricted mode still works. No live Codex/Cline tests are required.

## 1. Install the branch

From the existing graph-execution-preflight checkout:

    git pull --ff-only
    uv pip install --python ../gexec-preflight-venv/bin/python -e '.[pax]'
    ../gexec-preflight-venv/bin/python -m compileall -q src scripts tests
    ../gexec-preflight-venv/bin/gexec --help
    ../gexec-preflight-venv/bin/python -m graph_execution_runtime.cli doctor
    docker version

Start Docker Desktop yourself if the daemon is not running. Keep the existing Temporal dev server running. Do not change system Python or global Pax configuration.

## 2. Choose an immutable local image and existing model approval

    docker pull python:3.12-slim
    IMAGE=$(docker image inspect python:3.12-slim --format '{{index .RepoDigests 0}}')
    printf '%s\n' "$IMAGE"
    BASE_URL=http://localhost:20128/v1
    MODEL=openai:cx/gpt-6-luna

The pull is explicit operator setup, not worker network access. Inspect and approve the exact digest for your host. Set the provider key privately (zsh: read -rs 'GEXEC_PROBE_API_KEY?Provider API key: '; export GEXEC_PROBE_API_KEY; echo). Never paste it into a chat or profile. Check current model approval via the low-level CLI; if no current matching approval exists, archive the old approval explicitly and use:

    ../gexec-preflight-venv/bin/python -m graph_execution_runtime.cli approve-model \
      --base-url "$BASE_URL" --model "$MODEL" --confirmation "$MODEL"

## 3. Credential-free checks

    ../gexec-preflight-venv/bin/python -m unittest discover -s tests/qualification -p 'test_*.py' -v
    FIX=../gexec-offline-$(date +%Y%m%d-%H%M%S)
    ../gexec-preflight-venv/bin/python scripts/create_pax_fixture.py \
      --output "$FIX" --image "$IMAGE" --base-url "$BASE_URL" --model "$MODEL"
    ../gexec-preflight-venv/bin/python tests/qualification/docker_smoke.py \
      --image "$IMAGE" --wheelhouse "$FIX/wheels"

These exercise real Docker and Git but not live provider calls. Stop if any mandatory test fails.

## 4. Local live qualification (bounded two scenarios)

    ../gexec-preflight-venv/bin/python scripts/qualify_pax.py \
      --scenario L01 --output ../gexec-L01-$(date +%Y%m%d-%H%M%S) \
      --image "$IMAGE" --base-url "$BASE_URL" --model "$MODEL"

Only if L01 reports PASS, run the second fresh fixture:

    ../gexec-preflight-venv/bin/python scripts/qualify_pax.py \
      --scenario L02 --output ../gexec-L02-$(date +%Y%m%d-%H%M%S) \
      --image "$IMAGE" --base-url "$BASE_URL" --model "$MODEL"

L02 deliberately interrupts one disposable sandbox after a real command and the actual master after a durable verification. The external harness checks exact target identity and interrupts only the test's process/container. Each scenario writes qualification-receipt.json. Do not run a third scenario or share raw provider logs. A scenario PASS is evidence for this fixture only.

## 5. Normal project use

For a clean trusted Python repository, create a private profile using the schema generated by create_pax_fixture.py as an example. Adapt workspace, approved source/test path prefixes, write paths, wheelhouse and hashes, operator-approved task and final checks, immutable image digest, actual approved route and skill checkout. Put the profile outside the project; do not include keys. The independent oracle is optional for normal projects, but required for the fixture. Once per project:

    gexec setup --workspace /absolute/project --profile /private/profile.json

Then each run only requires:

    gexec run --plan /absolute/PLAN.md --workspace /absolute/project

All work publishes to a new local gexec-<id> branch, not the original checkout. The run receipt is under ~/.local/state/graph-execution/runs/<run-id>/FINAL_DECISION.json. Use gexec status --run-id <id> or gexec cancel --run-id <id>. No remote push, merge or automatic cleanup of the original checkout. GO means that project's admitted scope completed; it does not certify the product or all other projects. Only approved wheels, text changes and Python/pytest in isolated containers are supported. The current scratch cap is monitored, not a hard filesystem quota. Recovery only retries a proven discarded scratch attempt; unknown activity/process failure or uncertain publication stops. Request/token reservations are conservative and tool accounting does not include all built-in capability calls. Full F01–F13 and the final release predicate remain separate from these local probes.

### Planning validation recovery

Autonomous stage errors now identify the artifact and reason (for example `DURATION_UNIT_REQUIRED`) in `planning-validation.json`. The master can repair that artifact once without restarting the process. After a second validation failure, the planning stage is blocked and the supervisor stops. The analyzer still rejects missing units, malformed durations, cycles and unknown dependencies; there is no inferred default unit. Previous failed qualification records remain immutable.

### Phase-isolated Pax master

The supervisor now launches separate fresh Pax sessions for planner, team design, scope compilation and execution. It selects the next phase from verified manifest fingerprints and the bundle/final receipt; normal phase transitions are not restarts. Only the current phase's tool schemas are exposed. The total master request ceiling and conservative byte-based request/token reservations are unchanged; rejected request body sizes are recorded without contents. A single unexpected recovery is allowed across the run. The optional frozen profile fields `required_parallel_roots` (two disjoint approved write groups, capacity >=2) and `require_independent_review` enforce the explicit fixture concurrency and review requirements at planning, team and compiled scheduler gates. The fixture's actual plan/oracle and approved checks are unchanged. No tokenizer-specific accounting or arbitrary history truncation is claimed.

### Usage-aware resource accounting

The existing 1,500,000 aggregate charge ceiling, 120 total requests, 60 master requests, per-task limits and 60,000-byte context guard remain. Each request first reserves its conservative body-byte bound plus output allowance. Successful complete JSON/SSE responses with internally consistent provider-reported usage settle that reservation exactly once to reported input+output. Missing, malformed, interrupted or compressed/unobserved usage retains the full reservation. The master is capped at 1,000,000 charged units, with planning/compilation capped at 650,000, protecting at least 500,000 of the global allowance from master consumption. This is provider-reported accounting, not independent measurement or a guarantee of upstream tokenizer accuracy. An unexpected provider overrun is charged in full and subsequent admission fails closed when limits are exceeded. No response bodies or credentials are written to the budget ledger. Worker assignments now expose exact approved check argv; fixture acceptance requires the same approved unittest command to fail then pass.

### Executable team contract

The autonomous team gate rejects master-owned tasks, invalid ownership, role/hierarchy mismatches and reviewer writes before completing the team stage. Integration and cleanup are worker tasks; the logical master reviews and approves. The same ownership rules run again at bundle compilation. Scope diagnostics identify a validated task ID and a field or index without copying arbitrary provider text. The compiler still checks the frozen profile and source fingerprints, and invalid scopes cannot expand authorization. A repaired compilation receipt is marked prepared. Qualification skill-load evidence is evaluated independently of final verification.

### Bounded worker completion

Autonomous workers receive a small exact-path snapshot and compact role-specific instructions instead of loading the master skill again. Ordered batches (up to six scoped operations) and approved check indices reduce model round trips while each underlying operation remains budgeted. Explicit `submit_candidate` freezes a completed scoped proposal after actual approved checks; a subsequent request-limit/provider failure cannot erase that explicit submission. The master must still inspect and approve its digest and independent checks must pass. An unsubmitted request-exhausted candidate is retained separately as incomplete, never published or treated as success. The optional `required_peer_handoff` profile flag requires a unique pair of approved concurrent roots; the first must send a direct HANDOFF and the second must explicitly acknowledge that peer's received message. A master relay is not a substitute. Existing fixture plan and oracle are unchanged.

### Deterministic compact scope compilation

Preparation now accepts scopes-only input with exact read/write paths and approved check indices. Frozen team artifacts supply ownership, hierarchy and scheduled resources. Planned write groups constrain compact output paths; no write authorization is widened. Required root pairs receive deterministic scheduler priority without bypassing genuine conflicts. For explicitly authorized direct peer handoff, an exact receiver read of a sender write is narrowed and recorded in `scope-compilation.json` (no other read or resource is dropped). Downstream integration/review can read verified prerequisite outputs. Full extension input remains supported for existing callers. The original plan, checks and oracle are unchanged.

### Bounded supervisor shutdown and receipt recovery

The autonomous worker runs in its own local subprocess and process group, not an in-process asyncio task. Readiness is tied to its exact workflow/queue. Shutdown independently stops master, the exact Temporal workflow, worker and containers labeled with the run ID; workflow drain timeout can force-terminate only that workflow. Cleanup uncertainty is NO_GO. Early run identity is persisted before preflight. Qualification recovers the exact matching terminal disk receipt and intermediate evidence after abnormal exit, but cannot declare GO without a matching stdout receipt and clean exit. Existing historical receipts remain untouched. No other Temporal workflows, user processes or unrelated containers are targeted.

### Original requirements and functional task checks

Each autonomous worker receives a bounded exact segment of the original approved Markdown plan; longer plans expose explicit continuation via `read_source_plan(offset)`. Task summaries do not replace source requirements or expand authorization. Optional `required_checks_by_write_group` binds approved verification indices to actual write paths. Compact compilation adds missing mandatory indices and records the addition, while full extensions must include them. Final-text submissions and explicit tool submissions share the same worker-side approved-check gate. Request exhaustion without submission remains NO_GO. The order fixture now uses a public CLI component check with an in-memory substitute for the concurrently implemented validator and two different contract versions, plus the actual approved wheel. This checks the full CLI behavior before publication without depending on the validation root. The original plan, wheel, and final independent oracle are unchanged; the final oracle uses the real integrated validator. This is stronger task verification, not a replacement for final qualification.

### Exact directory-to-file contracts

An optional operator profile `directory_files` maps a declared directory group to an explicit list of permitted exact file targets. Compact compilation resolves only those declared aliases and records each read/write expansion in `scope-compilation.json`. Full extensions must name the exact files. Undeclared children, existing directory tokens and directory/file layout conflicts fail closed; no inferred permissions. The order fixture declares `order_cli` as a directory with `order_cli/__main__.py` as its exact target. The CLI component check additionally requires that file to exist. Other new directory names cannot be inferred reliably from a path string alone and should be declared explicitly. Original plan, wheel and final oracle remain unchanged.

### Master context economy

Preparation policy exposes the frozen task/owner contract, tracked inventory and one exact verification catalogue in a single response. The master can still read original artifacts if needed. Execution model-facing command receipts use check indices, exit codes, hashes and timing instead of duplicating embedded Python and file-operation content. Full proposal edits, attempt and proposal digests, and all original local audit receipts are unchanged; verification and publication still use the actual approved argv. The phase prompt avoids redundant reads and status calls. L02 reports all three recovery predicates even when execution is never reached. This does not increase the 60,000-byte request body limit or any model budget, and does not guarantee context headroom for arbitrary plans.
